# Clinical Ambient — 本地开发原型

React 前端（5174）→ Ingestion 接入服务（8003）→ Intelligence 智能服务（8002）。当前使用桌面上的 `clinical-ambient` 工程。

## 最新状态（2026-11-10）

这是本地开发原型，仅使用虚构测试数据；下方较早的开发记录保留作背景，当前行为以本节及对应说明文档为准。

- 英文统一工作台，默认虚拟患者 Alex；实时转写、录音回听、录后说话人分析、保守角色建议及人工更正。
- 实时转写默认使用 medium 延迟配置和通用问诊术语提示。录音最长 10 分钟；可选完整回听/说话人分析缓存最多 120 秒。
- 已确认文字经规则脱敏后显示；原文加密保存于本地，有 24 小时逻辑过期机制。密钥和本地数据不包含在仓库中。详见 [PRIVACY.md](PRIVACY.md)。
- 当前患者的本地历史记录导入、词法检索和来源引用；默认使用已确认对话，手动查询位于 Custom search。详见 [RAG.md](RAG.md)。
- 最新检查：71 项后端测试、20 项前端测试通过，双页面生产构建通过。云端模拟测试不能证明真实语音准确率。
- 尚未完成生产鉴权、公开部署验收、语义 RAG、SOAP 表单或临床准确率验收。

首次运行请在项目根目录创建 Python 虚拟环境并安装 requirements.txt，在 frontend 内运行 npm ci，然后回到项目根目录运行 .venv/bin/python scripts/start.py。API 密钥通过 scripts/configure_key.py 在本机配置，不能提交至 GitHub。

英文测试步骤见 [TESTING-EN.md](TESTING-EN.md)，界面说明见 [UI.md](UI.md)。完整前端构建命令：`npm run build -- --config vite.review.config.mjs`（在 frontend 内运行）。

## 启动

已安装依赖后，在 Mac 终端运行：

```sh
cd ~/Desktop/clinical-ambient
.venv/bin/python scripts/start.py
```

保持终端开启，访问 http://127.0.0.1:5174/ 。Ctrl+C 停止本次启动的三个服务。若端口占用，先到旧服务终端按 Ctrl+C；启动器不会结束其他进程。

首次安装（Python 3.11+、Node 24）：

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cd frontend
npm ci --cache .npm-cache
```

## 配置 API Key

```sh
cd ~/Desktop/clinical-ambient
.venv/bin/python scripts/configure_key.py
```

粘贴密钥后回车，终端不会显示字符。密钥只保存在本地 `.secrets/openai.json`（目录 700、文件 600），已被 Git 和 Docker 忽略。不要分享此文件，也不要把密钥发到聊天或写入 `VITE_` 变量。

智能服务每次请求读取密钥，保存后无需重启；环境变量 `OPENAI_API_KEY` 优先于文件。需 Audio Request 和 Realtime Request 权限，以及相应模型访问权限。页面“检查 API 配置”仅检查密钥是否存在，不调用 OpenAI，也不验证权限或余额。

## 实时转写

1. 在“边说边查看文字”中选择语言，勾选云端调用提示。
2. 如需录后区分声音，再勾选“保留录音用于说话人分析”。这会在本页内存保留最多 120 秒完整音频。
3. 点击“开始实时转写”，自行允许麦克风权限，读合成测试内容。
4. 点击“停止并确认最后一句”，等待待发送数量归零并显示完成。

模型 `gpt-live-transcribe`，`delay=low`，24kHz 单声道 PCM16，`turn_detection=null`。客户端约每 200ms 发送音频，检测停顿或停止时提交最终确认。临时文字与最终文字分别标注；根据 item ID 和前项链接排序、合并，避免按事件到达顺序乱序拼接。

路径：浏览器 → 接入服务 `/realtime/{session_id}` → 智能服务同名 WebSocket → OpenAI `wss://api.openai.com/v1/realtime?intent=transcription`。密钥只在智能服务使用。

- 音频、提交、结束消息都带连续序号；浏览器补传未确认消息，服务端去重。最多 30 秒内尝试恢复同一个云端连接，不自动开启第二个付费会话。
- 云端连接断开或后端重启会明确报错。停止时提交尾部音频，并等待所有片段的最终确认；超过 30 秒报错。
- 单次最长 10 分钟，最多 2 个并行云端会话，离线队列最多 8MB。
- 页面首字耗时从第一包音频入队计算，包含开头静音；停止后确认耗时从结束消息入队计算。均为当次测量，不是延迟保证。

## 停止后识别说话人

保留录音的完整会话停止后，点击“识别说话人（额外 API 费用）”。此点击才额外发送整段音频到 OpenAI 文件转写接口，使用 `gpt-4o-transcribe-diarize`、`response_format=diarized_json`、`chunking_strategy=auto`。实时模型本身不返回声音标签，因此录后结果独立展示，措辞可能与实时转写不同。

分析结果包含时间范围和说话人 A/B；先回听，再用下拉框人工确认“医生 / 患者 / 其他”。应用不从声音编号或对话内容猜测临床身份。只有一个声音时保留单说话人；没有标签的片段显示“说话人未知”，不会强行分成两人。一个人轮流读医生和患者台词并不等于两个声音。

- 分析最多 120 秒。超过上限会释放整段分析缓存，实时转写继续；不会把截断的片段冒充完整录音。请重新开始短会话测试。
- 录音回听、身份选择仅保存在本页；清空、新会话、刷新均会清除。音频不写本地数据库或音频文件。
- 智能服务按会话 ID 和音频/语言摘要缓存结果 30 分钟，最多 100 个会话，最多 2 个并行请求。同会话重复点击复用进行中的请求或结果，不静默重复调用。
- 明确的权限或额度拒绝可在修复配置后手动重试。超时或连接异常的结果未知，会缓存错误，避免自动重复计费。服务重启或缓存过期后，去重保证失效。
- 目前是录后声音聚类与人工身份确认，尚未完成自动医生/患者映射或“准确率超过 90%”的正式验收。

两个人交替读以下虚构台词，约 20 秒，每轮稍作停顿：

```text
医生：你好，请问你哪里不舒服？
患者：我咳嗽三天了，但没有胸痛。
医生：有没有药物过敏？
患者：我对青霉素过敏，目前没有服用其他药物。
```

## 其他对照实验

- “整段与停顿转写对照”：独立 WAV 文件请求，默认 `gpt-transcribe`。约 700ms 低音量停顿切分，最长 15 秒；整段模式最长 30 秒。硬上限切分会提示核对相邻片段。该实验未接入说话人分析。
- “麦克风与实时音频链路”：原 `/audio/{session_id}` 仅接收并丢弃音频，不调用云端；用于 ACK、断线补传和去重实验。

## 当前范围

已完成本地三服务通信、实时与文件转写、断线恢复实验、录后说话人分析和人工身份确认。以下仍待完成：云端公网三服务验收、语义检索与生成式 RAG 扩展、SOAP 表单。项目的“主题结束后 5 秒内更新表单”和“说话人准确率超过 90%”尚未验收。

只使用合成测试内容。数字、否定词、药名和身份均需人工核对。当前没有登录鉴权、生产限流及加密持久化，不应直接公开作为医疗系统。浏览器及服务端暂存音频/文字，刷新、崩溃或服务重启不保证恢复；OpenAI 云端处理遵循其 API 数据政策，不能宣称云端零留存。

## 完整录音文字复核页（2026-11-08）

打开 http://127.0.0.1:5174/review.html 。此页与原实时转写页独立，不会自动导航或清空旧页录音。

1. 点击“开始本地录音”，完整读完对话，再点击“停止录音”（最多 120 秒）；本地录制不调用云端。也可导入原页面播放器下载的本站 24kHz 单声道 PCM16 WAV。
2. 勾选发送测试音频的提示，点击“整段文字复核”。智能服务将完整音频一次提交给 `gpt-transcribe`，加入问诊领域提示和术语，不放入期望诊断、体温、病程或预设回答。
3. 需要声音标签时，再点击“识别说话人”，这会另调一次声音分析接口。两份文字独立显示，有内容差异时提示回听；不会自动把复核文字分给某个人。
4. 声音片段支持回听（时间范围前后各约 0.25 秒）、人工修订文字、调整单片段归属及恢复脱敏机器文本。修改会明确标记，脱敏后的机器文本仍可展开查看。该功能不能自动修复已漏掉的语音。

整段复核没有说话人标签或精确时间戳。复核也可能出现错词、标点或措辞变化，不保证比每次声音分析都更准确；需用相同录音对照。原来投诉的真人录音尚未在本次复核中重跑，不能宣称已消除该样本的错误。

`/text-review/{session_id}` 使用同样的原始 WAV 校验、来源白名单和后端密钥。结果缓存按会话与音频/语言摘要去重 30 分钟；明确权限或额度拒绝可手动重试，超时不自动重复调用。页面不自动连续计费。

双页面生产构建：

```sh
cd frontend
npm run build -- --config vite.review.config.mjs
```

Dockerfile 已使用此命令，产物包含 `index.html` 和 `review.html`。单独运行旧的 `npm run build` 默认只构建主页。当前开发启动命令无需变化。新版后端回归测试为 41 项（排除另跑的本机链路测试），未改动原有音频模块。


## 对话内容自动角色建议（2026-11-10）

两个页面在声音分析完成后自动检查对话线索，给身份下拉框填入建议，并显示“自动推测，待确认”。展开依据可查看支持该判断的原话。点击确认或手动选择才标为人工确认；手动改为未知也不会被建议覆盖。

此版本是浏览器本地规则，不调用额外 AI 接口、不增加 API 费用，不等于大模型语义理解。仅在两名说话人分别具备多类互补线索时建议医生/患者，不按 A/B 顺序强制分配。单人、多方、模糊、转述或混合角色线索保留未确定。复核页人工改过的文字/归属参与重新评估，已人工确认的身份保留。

尚未验证真人身份判断准确率超过 90%；规则可能漏判或误判。后续如需大模型推理，需单独接入文本接口并确认权限、费用及评测，不可把规则建议当作临床身份验证。
